# AI 插件

默认插件位于 `plugins/ai/`，使用与第三方插件相同的事件、工具、配置页和生命周期接口。

| 插件 | 功能 |
| --- | --- |
| `ai.chat` | 群聊参与、上下文、工具循环、会话、群记忆、用户画像及私聊通道 |
| `ai.tools` | 搜索、网页读取、下载、图片和文件发送、进度消息 |

两者默认不激活。`ai.chat` 声明依赖 `ai.tools`，启用时需一并选择。安装依赖使用 `uv sync --extra ai`，启动使用 `uv run --extra ai accbot serve`。

## 配置

在插件页面点击「AI · 群聊与会话」的配置按钮，选择默认模型、人格卡和聊天/主人/记忆整理提示词卡，并填写允许参与的群。一个群配置由连接 ID 和群 ID 定位；未启用的群不进入聊天观察和记忆。

人格卡和提示词由框架共享目录维护。默认人格中的 `[机器人名称]` 是供使用者编辑的文字占位符。机器人账号从入站事件的 `connection.bot` 获取，以独立 system 资料加入模型上下文；账号身份不依赖人格名称。

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `initial_probability` | 0.01 | 无活跃会话时的普通参与概率 |
| `busy_probability` | 0.30 | 无活跃会话时的高频参与概率 |
| `active_probability` | 0.20 | 活跃会话中的普通参与概率 |
| `active_busy_probability` | 0.20 | 活跃会话中的高频参与概率 |
| `busy_seconds` | 60 | 判定消息高频的时间窗 |
| `cooldown_seconds` | 5 | 概率触发的冷却时间 |
| `idle_seconds` | 180 | 最后一次唤醒后的会话空闲期限 |
| `context_budget` | 200000 | 总预算，含提示词、工具与输出预留；达到 95% 触发记忆整理，非供应商精确 token 数 |
| `output_reserve` | 16384 | 输出预留预算 |
| `max_tool_rounds` | 32 | 单轮聊天的模型调用次数上限，可设 1–256；不限制记忆整理 |

插件观察最近 15 条消息；新消息到来时，若此前 15 条均在高频时间窗内，则使用高频概率。@ 机器人可以绕过概率和冷却；群配置中的 `mention_users` 可限制允许 @ 唤醒的用户，留空表示该群所有成员。

## 会话与模型上下文

同一群的模型轮次按 FIFO 执行，不同群可以并发。回复、进度消息、图片和文件均通过 `ctx.messages` 交给适配器，发送回复时使用触发该轮的连接地址。通过 `ModelItem.from_message` 转换群友身份、时间、正文和引用快照，消息 ID 保留平台原始值；由框架合并相邻 user 消息，助手回复、工具调用、工具结果和供应商续接信息保持顺序，详见 [模型上下文](model-context.md)。

聊天插件通过 `@on_event(MessageSent)` 观察其他插件及框架直接发送的消息，按配置的群或私聊范围筛选，以机器人账号身份加入群聊历史。已有 session 时追加到 `waiting` 并写入 pending.json，在下一次正常唤醒或空闲总结时使用；没有 session 时只进入最近 15 条观察窗口，新会话取用这些记录。私聊初始上下文包含当前收到的消息和窗口中的外部发送记录，不携带此前的用户请求。

发送通知不创建或结束 session、不调用模型、不刷新唤醒时间和空闲定时器，也不触发预算整理。自身来源 `ai.chat` 的发送事件忽略，助手回复继续由模型返回结果直接保存；工具插件的发送作为已发生的聊天记录保留，不改写助手或工具轮次。消息使用已有观察窗口的消息 ID 去重，不维护额外回显索引。群文件上传仍使用独立的 FileSent 事件，不作为文本消息自动纳入该窗口。

人格、提示词、机器人账号、长期记忆、用户画像、工具 Schema 和输出预留都计入总预算。通过框架的 `accbot.models.count_tokens` 计数：文本使用内置 DeepSeek V4.1 tokenizer，消息封装为估算开销，每个图片或文件预留 8192 token；供应商的实际聊天模板及媒体处理可能不同。聊天轮次开始前及完成后检查预算占用：达到总预算的 95%（默认 190000）时，通过 `SummarizeMemory(reason="budget")` 整理已经完成的历史。新轮次开始前需要整理时，保留当前输入，先完成整理再回答。

系统提示词卡和人格卡由框架在预算预览及每次模型调用时读取运行目录文件，直接修改文件也会在下一次调用生效。插件和工具的补充提示词仍随激活保存快照，需要 reload 对应插件才更新。

预算整理保持 session 活跃，最后唤醒时间和空闲定时器不变。处理器只总结事件指定的历史前缀，保存群记忆成功后移除对应的 `record.turns`；整理期间新增的轮次和 `waiting` 消息保留，后续轮次读取更新后的群记忆。整理失败保留未完成的历史，在下次唤醒或会话到期时重试。聊天和总结均不通过滑动裁剪丢弃旧轮次。

预算事件、空闲结束及恢复重试共用前缀折叠逻辑。整理输入超预算，或画像工具调用使后续请求超预算时，将本批前缀轮数减半后重新整理；每批成功写入群记忆才删除相应前缀、更新记录 ID 并同步日志，再使用新记忆继续剩余历史。已保存的画像不会回滚，也不会自动重放上次工具调用。只完成部分前缀不视为整次整理成功；未处理历史继续留在 pending.json。最小单位是一轮完整历史，不拆开助手与工具协议；仅剩一轮仍放不下，或必要背景及整理轨迹本身超过预算时明确报错并保留记录。

画像按当前完整历史中的发言者及单层引用用户筛选，不因昵称相同合并身份。历史整理清除后，没有出现在后续上下文中的用户画像也不再注入。最近 15 条消息是独立的观察窗口，用于唤醒、初始上下文及按需看图，不是活跃 session 的历史长度限制。

工具可以并行执行。模型不需要发言时应单独、无参数调用 `stay_silent`；它同样通过 `ctx.tools.execute` 校验并执行，成功后聊天循环结束。查看消息图片时按需载入并压缩，图像作为对应 ModelItem 工具结果的 content，仅在当轮按调用 ID 回填。框架对两种协议统一在该批工具回执后生成补充 user 消息，注明调用 ID、原消息 ID 和资料用途；后续模型与工具轮次追加在其后，图片不再移动到上下文末尾。工具提示词要求按原话题决定是否参与，读图不意味着必须复述画面。日志和后续会话只保存原工具的文字回执，不保留 Base64，也不自动重新下载已查看的图片。引用在接收事件中已是独立的单层快照，插件不维护引用缓存、不补查原文，也不根据窗口内容改写引用。

聊天工具的调用资料通过 `ChatContext` 传递，显式声明原消息、机器人身份、主人通道标记和图片窗口；记忆整理使用 `MemoryContext`，声明本轮可更新画像的用户集合。两者均为插件定义的 `ToolContext` 子类，执行器负责注入，模型不能通过工具参数填写这些字段。上下文预算在 `Agent.budget` 中统一扣除输出预留、提示词与工具 Schema。

## 记忆与定时整理

记忆主键是稳定业务身份 `MemoryKey`：QQ 使用平台、会话类型和群号/用户号；其他平台还包含稳定租户作用域。连接 ID、插件激活 ID 和运行期会话 ID 不进入 QQ 记忆主键，因此重启、重载或更换连接后仍可接续同一群记忆。

```text
.accbot/data/plugins/
├─ ai.chat/
│  ├─ config/settings.json
│  ├─ memory/<MemoryKey 的 SHA-256 前 24 位>/
│  │  ├─ memory.json       # 稳定身份、路由提示、记忆和提交标记
│  │  └─ pending.json      # 待整理轮次及未消费消息
│  └─ profiles/
│     ├─ qq/user-<QQ号>.md
│     └─ <其他平台>/scope-<作用域>/user-<用户ID>.md
└─ ai.tools/downloads/    # 工具下载目录
```

记忆正文是自由的 Markdown，不要求固定字段或标题。推荐按需写“长期共识与背景”和“近期接续”，空节省略；人物只在必要时写昵称及用户 ID。默认提示词要求每次重写完整文档，合并重复、替换更正、移除失效安排和无价值细节。通常控制在 1200 字以内，复杂时尽量不超过 2000 字；这是内容取舍目标，不是程序截断规则。

`memory.json` 的 `memory` 字段保存 Markdown 字符串；外层仅保留稳定身份、路由提示和 `last_record` 提交标记，与正文一次原子写入。注入模型时只提供 Markdown 正文，不暴露这个 JSON 封装。正文硬上限为 64 KiB，空白输出拒绝提交。已有五字段正文在读取时转换为 Markdown，全部已有信息保留，下次成功整理时保存新正文。

活跃状态由内存中的 `channel.session` 表示，`pending.json` 只保存尚未整理的历史和待处理输入。预算整理成功后同步日志；没有剩余内容时删除该文件，session 仍可保持活跃。群记忆在每个聊天轮次开始时读取，同一轮工具循环复用该次读取的内容。预算整理只提交历史前缀，提交标记与整条待整理记录区分，避免落盘中断后误跳过尚未整理的新消息。

用户画像是独立的 UTF-8 Markdown 文件，每位用户一份，最多 16 KiB。是否创建由记忆整理模型判断，看到某个用户发言不会自动建档。QQ 画像以 QQ 号定位，跨群、跨连接及重载共享；其他平台以平台、稳定租户作用域和用户 ID 定位，目录中的特殊字符进行编码。群记忆侧重本群话题、关系及未完成事项，画像侧重个人长期偏好、称呼与目标。默认工具提示词要求整体替换，纠错、去重并移除临时状态，不追加更新日志；通常 200～500 字，尽量不超过 800 字，没有变化则不写入。建议篇幅不替代文件硬上限。

聊天和记忆整理都将匹配到的已有画像作为 system 背景资料放在会话长期记忆之后，含平台、用户 ID 和文档 revision。没有文件就不注入，也不扫描加载所有用户。单次模型工具循环通常使用画像快照；更新发生版本冲突时，整理循环在下一次请求前刷新画像背景供模型合并。重新开始整理某批历史时也读取最新画像，不静默截断正文。

实际唤醒时，消息处理器只取消并重设当前群的 `SummarizeMemory` 定时事件，字段携带稳定记忆身份和校验标记。普通消息未唤醒时不会延后期限。到期后，订阅处理器校验标记，将整理排入该群队列，等待已接受的轮次完成；无需遍历所有群。

整理模型使用所选记忆提示词卡，先按需调用 `ai.chat.update_user_profile(user_id, content, revision="")`，再输出重写后的完整群记忆 Markdown。记忆整理不限制工具循环轮数，不使用聊天的 `max_tool_rounds`；模型不再调用工具并返回有效记忆时完成。上下文预算、调用超时、错误处理和停用取消仍然有效。`content` 是完整画像，新建时 revision 留空；更新时传入画像或工具结果中的 revision。只有本次整理上下文中的发言者及引用用户可被更新。整理阶段不开放消息发送、网络、Shell 等工具，也不会把最终记忆发到群里。

画像工具的说明由 `prompts/tools/update_user_profile.md` 提供，默认记忆卡通过 `<tools_insert_prompt>` 引入。自定义卡片仍完全控制是否注入工具说明。成功或冲突回执都只返回状态与 revision，不回显完整画像。两个群同时更新同一用户时，旧 revision 不会覆盖新文档；返回 `conflict=true` 后，最新正文通过下一轮的画像背景提供，供模型合并后重试。

整理失败按 1、2、4、8、15 分钟安排重试，也会在下一轮对话前尝试。重启恢复待整理记录，不重放工具；结果不完整的工具调用标为结果未知。损坏的文件报错并保留，不用空记忆覆盖。

待整理记录使用 `Record` 数据模型，由 Pydantic 统一校验嵌套 ModelItem 并序列化为 JSON；恢复时只补齐中断的工具结果、并入未消费消息和标记会话结束，不手写字段转换。

每个画像文件独立原子保存，与群记忆不构成多文件事务。画像已更新但最终群记忆无效时，保留画像和群会话的待整理日志；重试读取最新画像重新整理，不盲目重放上次画像工具调用。并发版本检查适用于单个 accbot 进程。

修改配置或停用插件时保留待整理日志。插件通过 `ctx.stop_jobs` 最多等待当前聊天任务 5 秒，再取消未完成的聊天任务；框架已接受的后台工具仍可自然完成。恢复时通过 `ctx.messages.get_connection` 取得连接身份，不直接读取任务表或适配器表。旧激活的回复和定时事件不会投递给新实例。

## 私聊与工具范围

- 普通私聊由白名单筛选，需 @ 唤醒，采用无状态对话，不建立会话记忆；仍可读取该用户已有的画像，但不触发记忆整理和画像更新。
- 主人私聊由连接 ID 和用户 ID 筛选，逐条唤醒，维护独立记忆。
- 文件读写与 Shell 默认关闭，仅在配置主人并开启控制工具后提供给主人私聊。执行时再次核验真实入站消息的发送者与会话。

三类消息使用独立的 `@on_message` 订阅。框架提供通用身份过滤器，主人角色和工具范围由插件实现。普通群聊不会获得文件控制和 Shell 工具，也不会注入这些工具的提示词。

网络工具读取公开 HTTP(S) 地址，逐跳验证重定向，下载上限为 50 MiB。普通文件发送只能读取下载目录中的文件。图片使用内联数据发送；群文件上传要求协议端支持相应扩展，并能访问下载文件路径。网页搜索使用 Bing 和 DuckDuckGo 的 HTML 页面，外部站点的访问限制或结构变化会导致失败或空结果。

## 代码入口

| 文件 | 职责 |
| --- | --- |
| `chat/plugin.py` | 装饰器订阅、工具选择、配置更新 |
| `chat/sessions.py` | 消息观察、队列、会话、定时整理与恢复 |
| `chat/agent.py` | 模型与工具循环、上下文前缀、记忆整理调用 |
| `chat/context.py` | 类型化工具上下文、观察记录及中断工具结果补齐 |
| `chat/identity.py`、`chat/memory.py` | 稳定记忆身份及持久化 |
| `chat/profiles.py` | 用户画像文件、版本检查及按上下文身份选取 |
| `chat/settings.py`、`chat/frontend/` | 插件配置及页面 |
| `tools/plugin.py` | 网络与消息工具声明及公开接口 |
