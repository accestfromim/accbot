# accbot 架构与设计

accbot 是面向群体聊天的 Python AI 机器人框架。多个参与者、持续到来的消息、选择性发言和插件协作是主要场景。聊天策略由插件完整定义，框架提供事件、消息、模型和执行基础设施。

本文件描述当前框架的职责边界、公共契约和运行行为。接口改动应同步更新文档及相关测试。

## 实现范围

框架提供 OneBot 11 适配器与管理工作台。`plugins/ai/` 提供默认聊天和工具插件，聊天策略、上下文和记忆均位于插件内。测试夹具位于 `tests/fixtures/`，不参与运行时插件发现。

框架负责内部身份与消息模型、事件分发、消息发送、模型卡和模型协议、人格卡与系统提示词卡目录及持久化、提示词模板展开、工具执行、后台任务、定时器、插件发现与依赖、公开接口、激活与源码热重载，以及框架自身的配置保存。

插件包可以是代码包或纯资源包。纯资源包提供不可变文件快照与公开读取接口，适用于插件自有资源。人格卡和系统提示词卡由框架统一管理，提供共享目录、增删改查及导出。调用插件决定每次使用哪张系统提示词卡和人格卡；工具说明随工具注册，记忆整理的时机、上下文和结果处理仍由插件负责。

插件负责是否参与聊天、会话推进、上下文与工具组装、模型调用顺序、人格应用、记忆整理、内部参数和业务文件。无需强制的 ChatStrategy 接口、上下文序列化插件、权限系统或通用业务存储层。

官方聊天插件分别保存群会话记忆和共享用户画像。画像按稳定用户身份各存一份 Markdown，由整理模型按需建立；上下文仅注入窗口中发言者及引用用户的已有画像，置于会话记忆之后并计入预算。会话总结先允许画像工具循环，再验证和提交群记忆 JSON；画像并发更新使用文档 revision 检查。以上均为插件业务，不增加框架存储职责。

聊天的 max_tool_rounds 默认 32，表示一次聊天推进中最多调用模型的轮数，一轮可包含多个工具调用。记忆整理不使用该上限，持续执行工具循环直到模型返回完整记忆；预算、超时、错误和停用取消规则仍然生效。

官方插件的活跃 session 由内存状态标识，pending.json 是未整理内容的持久化日志。聊天轮次前后，按含提示词、工具和输出预留的总预算检查占用；达到 95%（默认 190000）发布预算整理事件。成功保存记忆后清除本次总结的历史前缀并同步日志，保持 session 活跃，保留并发到来的新消息。预算事件及会话结束整理共用前缀折叠：输入或工具循环超预算时缩小批次，按顺序保存群记忆、清除已总结前缀、更新记录 ID 后继续。失败保留未完成部分；无法再拆分的单轮或必要背景超预算时仍明确报错，不滑动丢弃内容。框架不接管这项业务策略。

画像更新的成功与冲突回执只包含状态和版本，不回显正文。遇到版本冲突时，整理循环在下一次模型请求前刷新画像背景，让模型获得最新版再合并；重试整理读取已保存的画像，不自动重放工具调用。

适配器属于框架源码，不是插件类型。新协议通过修改框架和提交 PR 添加。框架保持协议无关；首个实现是 OneBot 11。

## 身份与消息

- `platform` 表示 QQ、飞书等平台；`connection_id` 标识接入实例；`channel` 不用于表示平台。
- 用户、群、会话和消息 ID 都是字符串，身份引用带平台和作用域。接入连接用于路由，不能仅靠群号判断发送目标。
- User、Group、Member 是可序列化资料快照。ConversationRef 是会话地址，可关联群或话题。UserRef 的身份比较不依赖昵称。
- MessageChain 是有序内容片段；ChatMessage 包含会话、发送者、时间、引用快照及内容。Builder 构建不可变消息链。
- ChatMessage.reply_to 使用 MessageQuote 保存被引用消息的发送者、正文和时间，不保存指向原消息的引用，不递归展开。适配器在发布事件前补齐快照；原文获取失败时保留 content=None 的不可用快照，仍分发当前消息。消息 ID 用于框架查询、去重、发送回执等，不用于在插件窗口中关联引用。
- AssetRef 表示文件和媒体引用，支持 URL、平台文件 ID、路径和内联数据；按需读取，不在接收事件时强制下载。
- 模型上下文使用独立的 ModelItem，表达角色消息、工具调用、工具结果和供应商状态；不复用 ChatMessage。
- ModelItem 的发送者、时间、消息 ID、会话及单层引用是框架提供的可选结构化字段，由调用插件构造。模型层统一渲染并合并相邻普通 user 消息；system/developer、助手、工具及供应商续接项目保持边界和顺序。历史内容的稳定性由插件负责，不引入自动冻结会话状态。
- ModelItem.from_message 提供默认文本转换，使用群名片、保留身份和引用快照，以占位文字表示媒体且不下载。引用始终展示已有发送者和正文，不因原消息在窗口内而省略，不因窗口裁剪、原消息编辑或删除而改变；插件仍可自行构造 ModelItem 和多模态正文。
- 发送者及引用发送者显式标注用户 ID、平台和作用域。官方聊天插件从入站连接取得机器人自身账号，作为独立 system 资料并计入预算；身份判断规则仍通过可移除的插件提示词补充提供。
- 平台独有消息和事件保留命名空间及结构化载荷，不静默丢弃。
- OneBot 数组消息与 CQ 字符串映射到相同的内部消息链；正文、提及、引用和媒体保留语义，未知 CQ 段保留命名空间与参数。转义后的 CQ 字面文本不解释成提及或其他控制片段。

## 事件与分发

- Event 基类只放公共字段：事件 ID、稳定类型名及版本、发生与观测时间、来源、因果与关联 ID。平台事件额外带连接引用。
- 具体子类表示消息接收、发送回执、发送失败、编辑、删除、成员加入和退出、文件通知等；内置类型覆盖常用语义，其他 OneBot 事件走 CustomEvent。
- 插件可注册带命名空间的事件子类、发布事件，并使用装饰器和可组合过滤器订阅。`@on_message` 直接提供 sender、group、connection、platform、private 等条件。条件值可为身份对象、列表，或接收插件实例的同步配置读取函数；不通过字符串查找方法。框架没有主人等业务角色。
- 官方插件使用 `@on_event` / `@on_message` 声明事件入口，方法名称不参与路由。Plugin 基类只定义生命周期钩子；运行时动态订阅沿用同一所有权机制。
- 基类订阅包含子类；每个订阅对单个事件最多执行一次。事件及嵌套载荷不可变。
- 广播不修改事件、不由某个订阅者阻断其他订阅者。单个处理器异常隔离；同一订阅者在同一会话内保持顺序，跨会话可并发。
- 发布等待入队确认；完成等待单独提供。队列有界并提供背压。处理器内部嵌套发布不等待整次广播完成。
- 保留来源事件 ID 以去重，不承诺跨进程或平台操作恰好执行一次。
- 内置事件类型不随业务插件停用消失。自定义事件注册带 owner 和 activation_id，旧激活的载荷不能被重新解释为新版本事件。
- 入队时固定活跃订阅集合；分发与执行前重新检查订阅、事件类型和来源激活。旧后台结果可被框架诊断观察，不投递到新业务实例。

## 发送与模型

- 发送是返回回执的异步服务调用；MessageSent 是平台接受操作后的事实通知，不代表对方已读。
- `ctx.messages` 自动绑定调用插件；MessageSent.source_plugin_id 标识实际发送插件，直接调用 runtime.messages 时为 None，origin 保留对应激活身份。MessageSent.message 提供一次逻辑发送的 ChatMessage 快照，使用机器人身份和回执时间；多个消息 ID 对应的正文只记录一次，没有 ID 时快照为空。发送通知不伪装成接收事件，失效来源沿用总线的投递检查。
- 官方聊天插件订阅 MessageSent，观察已配置会话中其他来源的发送；活跃 session 追加 waiting 并落盘，未活跃时只记最近 15 条窗口。发送通知不触发 session 或模型、不刷新空闲计时；自身回复保留原有助手轨迹并忽略自身发送通知。
- 消息、图片和文件均通过统一发送管理器交给适配器；共用会话身份校验、错误处理和结果通知。通知失败不改变平台操作结果，也不覆盖原始发送异常。插件通过连接查询接口取得 ConnectionRef，不访问适配器实例表。
- 请求发送、发送回执和自身消息回显分别处理，回显与发送记录关联以避免重复入站。失败区分确定失败与结果未知，不自动重试有副作用的发送。
- OneBot 支持 HTTP、反向 WebSocket 和正向 WebSocket。正向连接由激活配置驱动，断线自动重连，停用及配置替换取消连接任务；已发出且未确认的 API 调用不随重连重发。两种 WebSocket 共用事件与回执接收逻辑，回执不受事件队列背压阻塞。
- 模型卡由框架配置产生，包含内部 ID、说明、端点、模型名、协议、能力与默认参数；密钥通过框架管理的环境变量引用解析。对外模型目录不暴露密钥值。
- 模型管理器按 ID 返回可复用的无会话客户端。上下文和工具均由调用插件传入。
- generate 同时接受 ModelItem 序列和原生消息数组的 JSON 字符串。字符串模式绕过内部消息渲染及全部提示词注入，忽略 system_prompt_id/persona_id；继续使用模型卡的端点、凭据、工具 Schema 和返回解析。不把文本中的角色标签猜测为协议字段。
- 支持 OpenAI 兼容 Chat Completions 与 Responses 原生工具调用。供应商编码和解析属于框架模型协议实现；其他协议显式添加，不猜测解析模型文本。
- GenerationResult 保留有序输出项目、工具调用关联、用量、结束原因及供应商延续状态。模型异常向调用方抛出。
- 当前使用完整响应；流式模型输出作为后续扩展，不伪造流式协议。
- 系统提示词卡由框架保存和提供前端编辑；调用插件通过 `generate(..., system_prompt_id=..., persona_id=...)` 选择，模型卡不保存选择。模型层在请求前组装选定模板。
- 系统提示词卡和人格卡的运行时目录在读取及渲染时现场加载配置文件，每次模型调用使用最新正文，包括工具循环后续轮次。无效或已删除的卡片明确报错，不回退旧内容；保存其他框架配置不重写卡片文件。插件与工具补充仍按激活保存快照。
- 模板正文的 `<persona>`、`<plugins_insert_prompt>`、`<tools_insert_prompt>` 分别插入所选人格、全部活跃插件补充、本次 tools 参数内工具的补充。仅替换模板自身，单次展开；不改写用户消息、历史或插入内容中的标记。缺少占位符时不自动追加。
- 每张卡是一份由用户完全控制的模板，没有固定前缀、后缀或分段顺序。三个占位符均可删除、重复、任意排序；工具 Schema 的提供不依赖工具说明占位符。
- 插件补充放在 `prompts/system.md`；工具补充放在 `prompts/tools/`，以 `@Tool(prompt_file="name.md")` / `@async_tool(...)` 绑定。激活读取 UTF-8 快照，失败回滚，停用撤销，重载更新；失效工具声明不能借同名新工具获得新提示词。

## 工具与后台任务

- Tool 装饰器声明工具及参数 Schema；工具归属插件，激活时注册、停用时撤销。工具可见集合和业务授权由调用插件决定。
- ToolDefinition 提供协议 Schema 序列化接口；模型调用、工具选择、执行结果分别使用 ModelItem、ToolCall、ToolResult。Annotated 参数约束同时用于声明和执行校验。
- 执行器验证参数、处理超时和错误；调用上下文不作为模型可修改参数暴露。
- 插件可继承 ToolContext 声明固定结构的业务字段；执行器识别子类注解并检查调用方提供的上下文类型，不将其写入工具参数 Schema。官方插件以独立的聊天、记忆上下文传递业务资料，待整理记录由数据模型统一校验与序列化。
- async_tool 声明后台执行工具，登记任务后立即返回 accepted 和 task_id；完成或失败通过内置任务事件报告。
- 停用不等待、不取消已启动的异步工具；允许自然完成和已有副作用，回执不保证被消费，不自动交给重新激活的新实例。
- 后台异常由框架接住。进程退出不保证任务继续，重启不恢复任务。
- 后台任务状态使用 JobInfo 记录，结果通知与任务执行分开处理，通知失败不将已完成任务改记为失败。内部工具装饰器配置使用不可变记录；协议参数和按 ID 索引仍使用映射。
- 插件可通过 `ctx.stop_jobs` 等待并停止指定的自有任务，其他任务不受影响。官方聊天插件用它关闭会话工作任务，不读取框架任务表，不取消已经接受的后台工具。尚未进入协程体就被取消的任务也会释放租约。
- 定时器通过 `ctx.schedule(event_or_factory, when, repeat=False)` 向事件管理器发布事件。`when` 为秒数或 timedelta 时表示延时，为 time 或 datetime 时表示指定时刻；repeat=True 分别表示固定间隔或每日同一时刻，datetime 可指定首次日期。无时区时使用服务器本地时区。固定间隔采用单调时钟，每日调度按日历计算，不补发全部错过的周期；夏令时缺失时刻跳过当天、重叠时刻每天只发一次。
- 定时器等待激活成功，到期检查创建者 activation_id；失效则不发布、不继续重复调度，无需停用时遍历取消。每次发布使用新的事件 ID 与观测时间，工厂在发布时调用；定时器不持久化。`ctx.cancel_timer(id)` 可取消本次激活安排的任务；已经入队的事件仍需业务校验标记。

## 插件与依赖

- 插件有稳定 ID、版本和依赖元数据，一个 ID 对应一个进程内实例。
- 依赖声明在激活前可读取。插件通过显式公开 API 和事件协作；跨插件直接导入实现模块不属于受支持的热重载契约。
- 框架不会自动激活依赖。启动和批量激活先校验完整候选集合：存在、版本、激活集合闭包和循环依赖；失败直接报错，通过后才按拓扑顺序激活。
- 未声明依赖造成的错误是未定义行为。前端提供依赖提示、推荐和启动前检查，后端仍独立校验。
- 注册项具有 owner_plugin_id 和 activation_id。激活成功后整体可见，失败撤销该次激活的所有暂存注册。
- 停用按依赖者优先递归执行，撤销工具、订阅、自定义事件和公开接口；尚未开始的排队处理器跳过，已启动后台工具自然完成。
- 公开 API 通过框架句柄访问；旧句柄在对应激活失效后不能开启新调用。
- 管理操作串行化，不因等待外部网络请求阻塞整个事件分发器。

## 源码热重载

1. 保存原活跃集合，确定目标及传递依赖者。
2. 读取新元数据，校验完整待恢复依赖图并计算顺序；预检失败保持旧实例运行。
3. 逆依赖顺序 unload 受影响实例；不停止无关插件。
4. 在独立激活命名空间中 load 新源码与新实例，插件自有子模块一并更新，共用第三方库不重载。
5. 按依赖顺序恢复原先活跃的受影响插件；不补选原本未启用的依赖。
6. 加载或激活失败撤销该次注册，依赖失败者保持停用；已恢复且不依赖失败者的插件可以继续运行。
7. 返回实际活跃集合和失败原因，不自动回滚旧源码，不迁移插件内存状态。

unload 是逻辑卸载；旧任务持有旧模块和对象直到完成。重新加载不复用旧 activation_id。代码执行产生的业务副作用不属于注册回滚范围。

插件的运行期业务状态，以及进行中的模型轮次与其他工具插件重载之间的一致性不作保证，不提供跨重载事务或状态同步层。

## 配置与管理

框架保存模型卡、人格卡、系统提示词卡、接入配置、密钥环境变量和插件激活集合。插件内部参数与业务数据自行保存。管理界面可以修改框架配置、校验依赖、激活、停用和重载；不内置聊天页面；提供人格卡和系统提示词卡编辑页面，供插件共享选用。

管理工作台采用侧栏导航，按插件、模型卡、人格卡、系统提示词、适配器（下设 OneBot）和密钥管理组织。本地默认无需令牌；远程访问令牌为可选配置，启用时浏览器使用会话 Cookie。模型 API Key、OneBot Access Token 与管理令牌用途分离。

插件列表递归发现目录并按实际子目录分组；勾选仅暂存选择，依赖推荐须由用户确认，后端不自动激活依赖。模型和 OneBot 使用逐步向导，直接接收密钥并自动生成环境变量引用。模型检测优先 Responses，再检查 Chat Completions，只在明确操作时发出有限测试请求；允许手动指定协议。新增 OneBot 配置默认未激活，激活后才接受协议事件，界面区分未激活、等待连接和已连接；HTTP 模式只显示已激活，不假定协议端在线。

框架配置、模型卡、适配器配置和插件激活集合拆分存放。详见 [目录约定](directories.md)。密钥只写入框架本地环境配置，读取接口仅提供名称、来源、使用位置和是否已设置，参数校验错误也不回显请求体。

插件可通过固定的 `frontend/index.html` 单根 div 组件及可选 JS/CSS 提供自己的配置侧栏。配置页支持未激活插件；由包根目录 `settings.py` 中的 `Settings(PluginSettings)` 接管校验、读取和保存，业务存储仍由插件自行管理。前端可读取框架模型卡、人格卡、系统提示词卡目录及全部已保存的接入配置摘要（含未激活配置）；保存成功后通过 `on_settings_changed` 通知活跃业务实例。默认聊天插件对不存在的接入配置 ID 显示提示，允许先保存规则再配置适配器。

插件前端随激活快照更新，旧页面在激活身份或源码版本变化后不能继续保存；关闭和失效时执行组件清理。组件用 Shadow DOM 隔离样式。详情和示例见 [插件配置页面](plugin-frontend.md)。

## 错误与运行边界

统一错误码覆盖配置、依赖、参数、供应商、超时、不支持、未知事件、激活失效和插件异常。异常带操作关联及确定失败或结果未知状态。插件可遵守统一协议；不遵守时仍在处理器、工具、后台任务及生命周期入口捕获并记录。退出和取消信号不作为普通插件错误吞掉。

## 检查项目

变更相关模块时核对以下契约；离线测试位于 `tests/`。

- [x] 身份、消息链和事件可序列化，嵌套载荷不可变。
- [x] 事件过滤、继承订阅、顺序、背压与异常隔离有效。
- [x] 依赖图在激活前整体校验，缺失和循环依赖报错，不自动补选。
- [x] 激活失败撤销暂存注册，卸载递归处理依赖者，重载使用隔离源码。
- [x] 自定义事件、定时器、公开接口、工具和排队回调不能跨激活误投。
- [x] 定时器支持单次延时、指定时刻、固定间隔和每日发布；时区、跨日、夏令时、无效参数及取消有明确语义，重复发布不复用事件 ID。
- [x] 后台工具接受后可自然完成，结果与异常不会投递到新插件实例。
- [x] 官方插件的消息发送、静默工具执行、任务停止及恢复时的连接查询使用公共服务，不直接访问任务表和适配器表。
- [x] 固定结构的业务上下文、任务状态和待整理记录有明确类型；上下文子类可注入同步、异步及后台工具，不进入模型参数，持久化格式保持一致。
- [x] 消息和文件发送共用路由与错误处理，结果通知失败不覆盖发送结果；平台消息 ID 保留用于路由、去重和按需工具。
- [x] 插件发送自动携带来源及激活身份，其他插件发言进入配置会话的观察窗口或待处理历史，自身回复不重复记录；观察发送事件不触发模型、session 或空闲计时更新。
- [x] 接收事件携带单层引用快照，模型展示发送者和正文；查询失败仍分发消息，窗口增删及持久化不改变已有引用。官方插件不缓存引用、不补查原文、不监听发送回执来维护引用。
- [x] OneBot 事件映射、发送回执、连接状态和未知结果有明确语义。
- [x] 正向 WebSocket 支持认证、收发、重连及状态展示；停用和配置替换取消连接任务，回执可在事件积压时继续处理，断线不重发未确认操作。
- [x] 数组与 CQ 字符串消息均通过正向 WebSocket、装饰器过滤、总线和实际 AI 插件完成唤醒与回复；转义文本不伪造提及。事件跟踪不输出消息正文或密钥。
- [x] Chat/Responses 共用内部类型，保留工具关联、多模态与供应商续接项目。
- [x] 相邻用户消息合并保留身份与引用，原生 JSON 输入绕过渲染及卡片注入。
- [x] 卡片模板完全由用户控制，插件与工具补充按当前激活和工具集合注入。
- [x] 系统提示词和人格的磁盘编辑在下一次模型调用生效，管理读取同步；无效文件不回退缓存，其他配置保存不覆盖卡片，插件补充维持激活快照。
- [x] 管理 API 不回显密钥，插件配置页面保留版本检查和清理机制。
- [x] 插件页面可读取含未激活配置的接入目录；聊天配置中接入 ID 不存在或暂时无法核对时仅提示，不阻止保存。
- [x] 群记忆使用稳定身份，定时整理只重设当前会话，恢复不重放工具。
- [x] 预算到达 95% 发布整理事件；成功后清理已总结的历史前缀，保持 session、空闲期限与并发新消息；失败保留未完成历史，前缀提交不会把剩余记录误记为已提交。
- [x] 整理输入或工具循环超预算时缩小前缀批次，逐批提交、更新 ID 并继续；部分提交不误判为完成，不能再拆分时保留记录。
- [x] 用户画像按稳定身份保存，按实际上下文窗口注入并计入预算；总结工具可按需建档与更新，版本冲突不覆盖新画像，失败保留待整理记录。
- [x] 画像更新成功和冲突都不回显完整正文，冲突后的最新画像通过下一轮背景提供。
- [x] 记忆整理的工具循环不限轮数，不受聊天 max_tool_rounds 影响，预算、错误及取消处理继续有效。
- [x] 模型调用使用当前连接的机器人身份，群聊与主人私聊的工具范围隔离。
- [x] 离线测试、静态检查与格式检查无需真实 QQ 或模型密钥。
